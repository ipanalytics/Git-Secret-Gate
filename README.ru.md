Хук на `pre-commit` и `pre-push`: смотрит строки, которые коммит или пуш собираются внести, и останавливает их, если там ключ, файл ключа или разрушительная команда. Ни сети, ни модели, ни сервиса за спиной — проверка это набор регулярных выражений, набор шаблонов имён файлов, тест на случайность строки и отчёт, который маскирует каждое совпадение, чтобы остановленный коммит не напечатал секрет ни в терминал, ни в журнал CI.

---

## Обзор

Ключи уходят из репозитория двумя дверями: индекс нового коммита и коммиты, которые пуш отправляет на удалённый сервер. Хук закрывает обе. `pre-commit` смотрит то, что подготовил `git add`; `pre-push` смотрит коммиты внутри диапазона, который вот-вот уедет, — именно там ключ переживает rebase, amend или revert.

Правила здесь — данные, а не код: 33 правила лежат в одной таблице и делятся на ключи (16), разрушительные команды (10) и политику по именам файлов и хостам (7). Свои правила встают в ту же таблицу через `extra_rules` в `secret-gate.toml`, поэтому правило под конкретный контур — одна строка конфига, а не форк.

Всё детерминировано. Хук не может «пропустить» из-за недоступной модели и не может вылить ключ в журнал: отчёт печатает маску и длину совпадения, но не значение.

## Устройство

```
индекс / диапазон git
        │
        ├── pre-commit  ─→ secret-gate check --staged
        └── pre-push    ─→ secret-gate check --range origin/main..HEAD
                                   │
                                   ▼
                    разбор diff, остаются только добавленные строки
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
      правила по тексту    правила по имени       тест на случайность
      (ключи, команды,     (ключевые файлы,       (длинные случайные
       приватные адреса)    .env, хранилища)       строки)
              │                    │                    │
              └────────────────────┼────────────────────┘
                                   ▼
                        находки → сведение по строгости
                        block / warn, переопределения из конфига
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
            отчёт для человека (маски)      запись --json
            код 1 при блокирующей находке   для конвейера CI
```

Разборщик diff оставляет только добавленные строки и имена файлов. Находка несёт id правила, строгость, файл, номер строки и маску; отчёт сортирует по файлу и строке, поэтому вывод читается как ревью, а не как дамп сканера. Конфиг ищется от рабочего каталога вверх до ближайшего `secret-gate.toml` или `secret-gate.json` — одна политика на корень дерева и никаких флагов в хуке.

## Возможности

- **Два хука, одна политика.** `pre-commit` смотрит подготовленный diff, `pre-push` — диапазон ревизий, поэтому изменённый или перебазированный коммит проверяется ещё раз перед отправкой.
- **Маскированный отчёт.** Остановленный коммит печатает `ghp…(40 chars)`, а не токен. Та же маска идёт в запись JSON — из-за этого хук безопасно запускать в CI.
- **Правила как данные.** 33 встроенных правила по ключам, командам и именам файлов плюс `extra_rules` в конфиге для того, что специфично для конкретного контура.
- **Политика по именам файлов.** `id_rsa`, `.env`, `*.pem`, `.p12`, `credentials`, `.netrc` и соседи ловятся по имени, поэтому файлу ключа не нужна узнаваемая строка внутри, чтобы быть остановленным.
- **Тест на случайность.** Длинные случайные литералы, которых не описывает ни один шаблон вендора, всё равно всплывают предупреждением.
- **Тишина по строке.** `secret-gate: allow` в строке или путь в `ignore_paths` глушит находку, не ослабляя остальное дерево.
- **Коды выхода, понятные скрипту.** `0` — чисто, `1` — находки, `2` — ошибка конфига; разбирать человеческий вывод не нужно.
- **Быстро и офлайн.** Проверка — локальные регулярные выражения по diff: миллисекунды, работает и на машине без сети.

## Быстрый старт

```bash
git clone https://github.com/ipanalytics/Git-Secret-Gate.git
cd Git-Secret-Gate
python3 -m venv .venv && . .venv/bin/activate
pip install -e .

# дальше в том репозитории, который надо защитить
cd /path/to/your/repo
secret-gate install          # пишет .git/hooks/pre-commit и .git/hooks/pre-push
secret-gate init             # пишет стартовый secret-gate.toml
```

```console
$ secret-gate check --staged
secret-gate: 2 finding(s) in 1 file(s) (1 blocking, 1 warning)

app.py:1  [warn] high-entropy-string  ghp…(40 chars)
```

## Использование

| Команда | Что делает |
| --- | --- |
| `secret-gate check --staged` | Смотрит индекс — ту же картину, которую создал бы коммит. Режим по умолчанию. |
| `secret-gate check --range origin/main..HEAD` | Смотрит все добавленные строки диапазона ревизий, для пуша. |
| `secret-gate check --last` | Смотрит только последний коммит. |
| `secret-gate check --file path/to/file` | Смотрит один файл с диска. |
| `secret-gate check --stdin` | Смотрит текст из конвейера. |
| `secret-gate install` | Пишет два хука в `.git/hooks/`; чужие файлы с такими именами не перезаписывает. |
| `secret-gate init` | Пишет `secret-gate.toml` с комментариями и значениями по умолчанию. |
| `secret-gate rules` | Печатает все активные правила со строгостью, видом и подсказкой. |

Полезные переключатели: `--json` печатает запись вместо строк, `--quiet` молчит и только ставит код выхода, `--warn-as-error` повышает предупреждения, `--no-entropy` отключает тест на случайность, `--limit N` ограничивает вывод, `--config PATH` указывает конкретную политику.

**Коды выхода**

| Код | Значение |
| --- | --- |
| `0` | Блокирующих находок нет (предупреждения могут быть в списке). |
| `1` | Есть хотя бы одна блокирующая находка: коммит или пуш надо остановить. |
| `2` | Конфиг сломан: у правила нет шаблона, регулярное выражение не компилируется. |

## Правила

Живую таблицу печатает `secret-gate rules`. Что покрыто:

| Вид | Сколько | Примеры |
| --- | --- | --- |
| `secret` | 16 | токены GitHub, GitLab, Slack, Telegram, Google; ключи AWS и OpenAI; секреты Stripe; JWT; заголовки приватных ключей; пароли внутри URL; IBAN |
| `command` | 10 | `rm -rf` по корню, `dd` на устройство, `mkfs`, `chmod 777 /`, `curl … \| sh`, force-push, перезапись истории, fork-бомба |
| `policy` | 7 | приватные адреса, пути домашнего каталога, имена внутренних хостов и правила по именам файлов: ключевые файлы, `.env`, хранилища доступов |

Строгость считается отдельно от вида: 26 правил блокируют, 7 предупреждают. Предупреждение — это строка, которую должен прочитать человек, а не строка, останавливающая коммит; исключение — включённый `warn_as_error`.

## Конфигурация

`secret-gate.toml` (или тот же объект в `secret-gate.json`) ищется от рабочего каталога вверх.

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `kinds` | список | `["secret", "command", "policy"]` | Какие виды правил активны. |
| `warn_as_error` | bool | `false` | Считать предупреждения блокирующими. |
| `check_entropy` | bool | `true` | Включён тест на случайные литералы. |
| `ignore_paths` | список | `["tests/fixtures/**", "*.lock", "node_modules/**"]` | Шаблоны путей, которые хук не смотрит. |
| `ignore_rules` | список | `[]` | Id правил, заглушённых в этом репозитории. |
| `extra_rules` | список | `[]` | Свои правила, той же формы, что встроенные. |

```toml
[[extra_rules]]
id = "internal-hostname"
pattern = "\\b[a-z0-9-]+\\.our\\.lan\\b"
severity = "block"
kind = "policy"
hint = "an internal host name: keep it in a local config."
where = "text"          # "text" — по строке, "path" — по имени файла
```

Правило с `where = "path"` сравнивается с именем файла так же, как встроенные правила политики: именно так собственное соглашение об именах становится условием проверки.

## Что на выходе

**Отчёт для человека** — блок на каждую находку, сгруппированный по файлу и строке, в конце — причина остановки и три выхода: поправить строку, поставить `secret-gate: allow` или внести путь в конфиг.

**Запись JSON** (`--json`), достаточно устойчивая, чтобы её хранить:

| Поле | Значение |
| --- | --- |
| `summary.findings` | Всего находок. |
| `summary.blocking` / `summary.warnings` | Разбивка по строгости. |
| `summary.files` | Файлы, где есть хотя бы одна находка. |
| `summary.failed` | Остановлен ли коммит. |
| `summary.warn_as_error` | Повышены ли предупреждения. |
| `findings[].rule` / `.severity` / `.kind` | Какое правило сработало и как оно классифицировано. |
| `findings[].path` / `.line` | Где сработало. |
| `findings[].masked` | Маска и длина совпадения — но не значение. |
| `findings[].hint` | Что с этим делать. |

## В конвейере CI

Хук работает и шагом конвейера; запись — та часть, которую читает ревьюер.

```yaml
- name: secret gate
  run: |
    pip install git+https://github.com/ipanalytics/Git-Secret-Gate.git
    secret-gate check --range "origin/${{ github.base_ref }}..HEAD" --json > gate.json
```

Ненулевой код валит шаг, а `gate.json` уходит артефактом с маскированными находками.

## Эксплуатация

- Хуки я ставлю во все репозитории на машине одной командой; `secret-gate install` идемпотентен и умеет убирать свои файлы, поэтому удаление — это удаление файла, а не поиск по конфигам.
- Пуш, переписывающий историю, проверяется дважды: когда коммиты создаются и когда диапазон уезжает. Второй проход ловит ключ, который попал в ветку до появления хука и пережил rebase.
- Документация и фикстуры намеренно не исключены по умолчанию. Если поддельный токен в фикстуре законен, помечай строку через `secret-gate: allow`, а не расширяй `ignore_paths`: исключённый каталог остаётся исключённым и после того, как фикстура исчезла.
- Отчёт и есть интерфейс. Всё, чему нужно исходное значение — ротация, запись об инциденте, — берёт его у провайдера, а не из вывода хука.
- `--quiet` существует для задач по расписанию и для хуков, где человек видит только код выхода.

## Границы проекта

Хук покрывает то, что видно в diff: строки добавленного, имена добавленных файлов и команды внутри этих строк. Он не сканирует историю, не проверяет ключ у провайдера и не отзывает его, и не решает, настоящий ли это ключ, — это решение остаётся за тем, кто читает отчёт.

## Сценарии

- **Репозиторий, в который ключ не должен попадать.** Хук — последний рубеж перед отправкой на удалённый сервер, и он достаточно дешёвый, чтобы стоять на каждом коммите.
- **Машина с несколькими репозиториями под одной политикой.** Один `secret-gate.toml` в корне дерева, найденный поиском вверх, держит политику в одном файле.
- **Конвейер, проверяющий pull request.** `--range base..HEAD --json` превращает хук в шаг CI, вывод которого читает ревьюер.
- **Правило контура, которого не знает ни один публичный сканер.** Имя внутреннего хоста, соглашение об именах фикстур, приватный диапазон адресов — `extra_rules` ставит это в ту же таблицу.
- **Машина без сети.** Ни сети, ни модели, ни собственного ключа.

## Ограничения

- Хук читает diff, а не историю. Ключ, который уже лежит в прошлом репозитория, там и остаётся: хук останавливает следующий, а ротация — отдельная работа.
- Шаблоны описывают форму, а не правду. Аккуратно сделанный поддельный токен будет показан, а настоящий ключ в незнакомом формате может пройти; тест на случайность сужает этот зазор, но не закрывает его.
- Хук не знает, действует ли ключ до сих пор. Проверка и отзыв — дело API провайдера.
- Правила по именам зависят от имён. Ключевой файл, переименованный во что-то обычное, для них невидим.
- Набор правил субъективен; `ignore_rules` и `kinds` существуют потому, что реальный репозиторий всегда с чьими-то настройками не согласен.

## Тесты

```bash
python -m pytest -q      # 21 тест
ruff check . && ruff format --check .
```

Набор покрывает таблицу правил (уникальные id, допустимые строгости), каждый класс находок, маскирование отчёта, метку `allow`, разбор diff, поиск конфига и свои правила, запись JSON и коды выхода командной строки.

## Развёртывание

Пакет ставится в то окружение, из которого будет запускаться хук:

```bash
pipx install git+https://github.com/ipanalytics/Git-Secret-Gate.git   # одна команда на машину
secret-gate install                                                  # по репозиторию
```

Хук запоминает интерпретатор, которым его поставили, поэтому репозиторий, открытый на машине без этого интерпретатора, громко падает на хуке, а не пропускает проверку.

## Дисклеймер

Хук уменьшает вероятность того, что ключ уйдёт с машины, но не отменяет ротацию ключа, который уже был опубликован. Остановленный коммит — повод прочитать строку, а не доказательство, что репозиторий чист.
