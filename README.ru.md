# Git-Secret-Gate

_English version: [README.md](README.md)_

Git-хук, который останавливает утечку ключа или разрушительную команду **до** того, как они уйдут с
машины. Ни сети, ни модели, ни сервиса — несколько миллисекунд на `git commit` и `git push`.

## Зачем это нужно

У каждой утёкшей ключа одна и та же история: он уже лежал в файле в момент коммита. После пуша
единственное лечение — ротация, а в публичном репозитории ключ был публичным всё время, пока его не
заметили. Ревьюер его пропускает, потому что диф читают на логику, а не на энтропию, и именно тот
коммит, где это важно, обычно содержит ещё сорок правок.

Есть сканеры, которые решают эту задачу по сети и по чужому списку правил. Этот — маленькая
офлайн-половина работы: свои правила, в своём репозитории, локально, а вывод сделан так, чтобы его
можно было вставить в задачу или в лог CI без самого секрета внутри.

## Что проверяет

33 правила в трёх группах; свои добавляются в ту же таблицу.

**Учётные данные** — приватные ключи (PEM/OpenSSH/PGP), токены GitHub и GitLab, боты Slack и
Telegram, ключи Google, OpenAI и Anthropic, идентификаторы AWS и Stripe, JWT, логины и пароли в URL
(`https://user:password@хост`), IBAN, плюс ловушка на энтропию для строк, которые выглядят ключом,
но не подходят ни под один известный формат.

**Разрушительные команды** — `rm -rf /`, `dd` и `wipe` по устройству, `mkfs`, `chmod -R 777 /`,
`curl … | bash`, `git push --force` в общую ветку, перезапись истории, fork-бомбы.

**Утечки обстановки** — приватные адреса, домашние пути с настоящим именем пользователя, внутренние
имена хостов и ключевой материал по имени файла (`.env`, `id_rsa`, `*.pem`, `credentials`, `.netrc`).

Отчёт никогда не печатает совпадение целиком. Остановленный коммит сообщает правило, файл, строку и
замаскированное значение (`ghp…(40 символов)`) — этого достаточно, чтобы узнать ключ, и бесполезно
для того, кто читает лог CI.

## Установка

```sh
pip install git-secret-gate          # или: pipx install git-secret-gate
secret-gate install                  # пишет .git/hooks/pre-commit и pre-push
secret-gate init                     # пишет secret-gate.toml со всеми опциями в комментариях
```

Дальше — в том репозитории, который важен:

```sh
secret-gate check --staged           # то, что сделает хук pre-commit
secret-gate check --range HEAD~5..   # коммиты, которые пуш собирается отправить
secret-gate rules                    # вся таблица правил с пояснениями
```

Коды возврата рассчитаны на хуки и CI: `0` — чисто, `1` — есть блокирующее (или предупреждение, если
включён `warn_as_error`), `2` — ошибка вызова или битый конфиг. `--json` отдаёт то же самое данными.

## Что делать с находкой

Три способа, по убыванию правильности:

1. Исправить — увести значение в переменные окружения и ротировать то, что утекло.
2. Пометить строку: `secret-gate: allow` прямо в строке — это то, что нужно тестовой фикстуре.
3. Заглушить правило или путь в `secret-gate.toml` (`ignore_rules`, `ignore_paths`).

Ложное срабатывание на фикстуре — ожидаемая вещь; для этого и есть метка, и поэтому одна и та же
находка не выводится дважды.

## Чем не является

Это не сканер истории: он смотрит на коммит и на пуш, а не на 40 000 старых коммитов. Это не замена
хостинговому сканеру, который знает про утечки в чужих репозиториях. И он не поймает секрет,
собранный во время выполнения из трёх безобидных половинок — этого не умеет ни один список правил.

## Настройка

```toml
kinds = ["secret", "command", "policy"]
warn_as_error = false
ignore_paths = ["tests/fixtures/**", "*.lock"]
ignore_rules = []

[[extra_rules]]
id = "internal-hostname"
pattern = "\\b[a-z0-9-]+\\.our\\.lan\\b"
severity = "block"
kind = "policy"
hint = "внутреннее имя хоста: место ему в локальном конфиге."
```

`where = "path"` заставляет правило смотреть на имя файла, а не на строку — в той же форме, что и
встроенные правила про ключевой материал.

## Структура

```
git_secret_gate/patterns.py   33 правила как данные: id, вид, важность, шаблон, пояснение, где искать
git_secret_gate/scan.py       поиск совпадений, энтропия, маскировка, метка разрешения
git_secret_gate/policy.py     secret-gate.toml / .json, свои правила, заглушки
git_secret_gate/diff.py       добавленные строки диффа: индекс, рабочее дерево или диапазон
git_secret_gate/report.py     отчёт для человека и то же самое в JSON
git_secret_gate/cli.py        check, install, init, rules
tests/                        21 тест, включая проверку «маска не выдаёт секрет»
```
